## 为什么隐私保护是选机场的第一道关

很多人选机场只看速度和价格，却忽略了最关键的事：**你把所有流量都交给了这家服务商**。一旦服务商记录并泄露你的真实 IP、访问行为、登录账号，后果远超「看不了视频」。

| 风险类型 | 具体危害 | 发生场景 |
|---------|---------|---------|
| 流量日志泄露 | 真实 IP 与访问站点被关联 | 服务商被入侵或配合调取 |
| DNS 污染溯源 | 明文 DNS 暴露访问域名 | 未启用加密 DNS |
| 账号关联 | 同一邮箱/支付账号暴露身份 | 用真实信息注册 |
| 协议特征识别 | 流量被识别并阻断 | 协议未混淆 |
| 中转节点窃取 | 中转服务器可看到明文 | 不信任的中转链路 |

**结论**：速度决定体验，隐私决定安全。没有隐私保障的「快」，等于把把柄交出去。

## 无日志政策深度解析

### 什么是真正的「零日志」

「无日志」不是一句广告语，而是一套可被验证的工程实践：

1. **不记录连接日志**：不保存「谁、在何时、连接了哪个节点」。
2. **不记录流量日志**：不保存你访问了哪些域名、传输了多少数据。
3. **不记录真实 IP**：出口节点不落盘源 IP。
4. **内存级会话**：临时会话仅存于内存，重启即清空。
5. **可审计证明**：愿意接受第三方审计或开源客户端。

### 如何验证一家机场是否真的无日志

| 验证手段 | 可信度 | 操作方式 |
|---------|-------|---------|
| 第三方独立审计 | ★★★★★ | 查看审计机构公开报告 |
| 开源客户端 | ★★★★ | 代码可自查流量走向 |
| 历史安全事件 | ★★★ | 搜过往是否泄露过日志 |
| 司法管辖地 | ★★★ | 位于隐私友好司法区 |
| 口头承诺 | ★ | 仅宣传语，无证据 |

### 红旗信号（假无日志特征）

- 要求实名认证才能注册
- 用「赠送流量」诱导绑定社交账号
- 退款需提供身份证明
- 节点常年不变且无审计
- 客户端闭源且请求异常权限

## 隐私保护措施清单

一份合格的隐私保护方案至少应覆盖以下 7 项：

1. **端到端加密传输**：AES-256-GCM / ChaCha20-Poly1305。
2. **加密 DNS（DoH / DoT）**：避免运营商窥探域名。
3. **Kill Switch（断网保护）**：隧道断开时自动阻断流量。
4. **IP/DNS 泄漏防护**：定期做 WebRTC、DNS 泄漏测试。
5. **协议混淆**：降低流量被识别概率。
6. **独立入口与出口**：入口只做转发，不掌握明文。
7. **匿名支付**：支持加密货币或隐私友好的支付方式。

### Clash 中的隐私关键配置

```yaml
# 关闭系统代理泄漏风险
dns:
  enable: true
  enhanced-mode: redir-host
  nameserver:
    - https://1.1.1.1/dns-query   # DoH，避免明文 DNS
  fallback:
    - https://8.8.8.8/dns-query

# 防止 DNS 泄漏到非代理链路
rules:
  - DOMAIN-SUFFIX,1.1.1.1,DIRECT
  - GEOIP,CN,DIRECT
  - MATCH,PROXY
```

> 提示：开启 `enhanced-mode: redir-host` 或 `fake-ip` 可显著降低 DNS 泄漏风险。

## 数据加密技术对比

### 对称加密算法

| 算法 | 强度 | 性能 | 适用场景 |
|------|------|------|---------|
| AES-256-GCM | 极高 | 高（需硬件加速） | Shadowsocks / VMess |
| ChaCha20-Poly1305 | 极高 | 高（移动端友好） | 手机 / 低功耗设备 |
| AES-128-GCM | 高 | 极高 | 大流量转发 |
| RC4 / 旧算法 | 低 | — | 已淘汰，禁用 |

**建议**：桌面端优先 AES-256-GCM；手机与路由器优先 ChaCha20，省电且抗侧信道。

### 握手与密钥交换

- **TLS 1.3**：现代协议首选，握手更快、前向安全。
- **ECC（椭圆曲线）**：比 RSA 更短更安全的密钥。
- **前向保密（PFS）**：每次会话独立密钥，历史流量不会被回溯解密。

## 主流安全协议对比

| 协议 | 加密 | 混淆 | 性能 | 隐私友好度 |
|------|------|------|------|-----------|
| Shadowsocks | AEAD | 弱 | 高 | ★★★★ |
| VMess | AEAD | 中 | 中 | ★★★★ |
| VLESS | 无内置 | 需配合 | 高 | ★★★（需 TLS） |
| Trojan | TLS | 强 | 高 | ★★★★★ |
| WireGuard | Curve25519 | 无 | 极高 | ★★★（特征明显） |
| Hysteria2 | 混淆 | 强 | 高 | ★★★★ |

**隐私优先排序**：Trojan（TLS 伪装成 HTTPS）> VLESS+TLS+Reality > VMess > Shadowsocks。

### Reality 技术简介

VLESS + TLS + Reality 让代理流量在被动观测下与正常 HTTPS 网站无法区分，大幅降低被特征识别的风险，是当前隐私与抗封锁兼顾的优选。

## 匿名性测试方法

### 自测清单

1. **IP 泄漏测试**：访问 ipleak.net，确认显示节点 IP 而非真实 IP。
2. **DNS 泄漏测试**：确认 DNS 服务器为代理提供方而非本地运营商。
3. **WebRTC 测试**：浏览器关闭 WebRTC 或走代理，避免真实 IP 暴露。
4. **流量特征测试**：用 Wireshark 抓包，确认外层为 TLS 而非明文。
5. **时间关联测试**：多次连接，确认出口 IP 不固定绑定账号。

### 匿名注册建议

- 使用一次性邮箱注册
- 不绑定社交账号
- 用隐私友好支付方式
- 客户端不开启「上报诊断」
- 不要在多个机场复用同一昵称

## 常见误区与避坑指南

### ❌ 误区一：「免费的就是赚到」

免费机场往往靠**售卖用户数据**盈利。你的访问记录、账号信息可能成为商品。

### ❌ 误区二：「HTTPS 网站本身已加密，不需要代理」

HTTPS 只加密内容，但**域名和真实 IP 仍对网络中间人可见**。代理解决的是「谁在访问」的暴露问题。

### ❌ 误区三：「协议越新越安全」

新协议若未配合 TLS / 混淆，特征反而更明显。安全 = 加密 + 混淆 + 无日志，三者缺一不可。

### ❌ 误区四：「节点越多越隐私」

节点数量与隐私无关。关键看是否记录日志、是否可信中转。

### ✅ 正确做法

- 选有审计或开源证据的机场
- 强制开启加密 DNS
- 定期做 IP / DNS 泄漏自测
- 匿名注册、隐私支付

## 常见问题 FAQ

**Q：机场能看到我访问了什么网站吗？**
A：若机场记录流量日志且未加密 DNS，理论上可见域名。选无日志 + 加密 DNS 的机场可消除此风险。

**Q：开了代理还会 IP 泄漏吗？**
A：会。WebRTC、DNS 设置不当、Kill Switch 未开都可能导致泄漏，需逐项自测。

**Q：Tor 和机场哪个更隐私？**
A：Tor 匿名性更强但极慢；机场适合日常使用。高匿名需求可「机场 + Tor」叠加。

**Q：加密货币支付更安全吗？**
A：是，能切断支付账号与身份的关联，是隐私注册的重要一环。

**Q：如何快速判断是否 DNS 泄漏？**
A：访问 ipleak.net，查看 DNS 服务器是否来自你的运营商，若是则说明泄漏。
